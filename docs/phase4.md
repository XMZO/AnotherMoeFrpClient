## 实现了什么

### shared

- `model/share.go`：
  - `SharePayload`：分享快照，包括节点、full 的代理、p2p 的目标（`P2PTarget`）。
  - `SubscriptionParams`：订阅参数，包括 template 选的节点和订阅者自己的代理、p2p 的本地绑定（`P2PBind`）。
  - `BuildRuntime`：把快照和订阅参数组装成可以直接运行的配置。
- `api/shares.go`：分享和订阅相关的请求、响应结构体。`SubscriptionSummary` 补全了：可选节点、p2p 目标、订阅参数，都不含机密。
- `validate/share.go`：按分享类型校验快照和订阅参数，包括重名、端口冲突、引用不存在的节点或目标。

### 服务端

- **接口**：PLAN 7.5 列出的分享与订阅接口全部实现。
  - 分享预览单独限流，每个用户每分钟 30 次（`Limits.SharePreview`）。
  - `GET /api/v1/state` 返回订阅摘要。
- **业务逻辑**（`internal/share`）：
  - 分享 ID 是 128 位随机数，用 base62 编码。
  - 创建时从来源配置里按节点 ID、代理 ID 取内容做快照。重新发布时沿用快照里已有的 ID。
  - 撤销是软删除，可以重复调用。过期时间、人数上限可以修改，也可以清除。
  - 人数上限的检查和插入在同一个写事务里完成（SQLite 用 `BEGIN IMMEDIATE`），不会超卖。
  - 分享发生任何变化时，分享者和所有订阅者的 `stateVersion` 都加 1。订阅发生变化时，订阅者的 `stateVersion` 加 1。
  - 审计日志新增 `share.create`、`share.republish`、`share.revoke` 三类记录。
- **旧库导入**（`internal/legacy/shares.go`）：按 PLAN 7.12 的规则导入旧分享和订阅。
  - 旧分享 ID（`share-<uuid>`）原样保留，用户手里存着的旧分享 ID 仍然可以用。
  - 旧分享没有记录来源配置，所以导入后不能"重新发布"。

### 客户端

- **订阅的存储**：订阅是缓存里一条只读条目，`origin` 为 `subscription`，条目 ID 就是订阅 ID。
  - 条目内容是服务端 runtime 组装好的可运行配置，和其他配置一样用 DPAPI 加密保存。
  - 引擎、启停、测速都和普通配置走同一套逻辑，离线时也能启动。
- **同步**（`cloudsync/subscriptions.go`）：
  - 拉 state 时，如果摘要里的分享版本或订阅版本和本机缓存的 runtime 对不上，就重新拉 runtime。
  - 分享被撤销或过期：清空条目内容（节点 token 和 secretKey 不再留在本机），正在运行就停止隧道。
  - 订阅在云端被删除：从缓存里删掉条目，正在运行就停止。
  - 正在运行的订阅被分享者重新发布：沿用"正在运行的配置被云端修改，是否应用"的提示。
  - runtime 拉取因为网络问题失败时，下一轮会做全量拉取，不会被 304 跳过。
- **分享服务**（`services/share.go`）：
  - 创建分享时要求来源配置是已同步完成的云端配置，否则提示先上传或等同步完成。
  - 订阅和修改订阅参数之后，立即拉取 runtime，不等下一轮同步。
  - 修改自己的订阅参数时，如果订阅正在运行，直接应用，不再询问（这是用户自己的修改）。
- **界面**：
  - 导航栏新增"分享"页：我的分享列表（类型、来源配置、订阅人数、过期时间、状态），可以复制 ID、重新发布、修改设置、撤销；"创建分享"向导。
  - "隧道"页左侧新增"订阅"分组和"+ 添加订阅"入口：输入 ID → 预览 → 按类型填参数 → 订阅。
  - 订阅的编辑区：
    - 顶部显示类型和分享者，被撤销或过期时显示红色提示。
    - full：只能查看。
    - template：可以编辑自己的代理。
    - p2p：只能改本地端口和启用开关。

## 与 PLAN 不一致或需要你决定的地方

按影响从大到小排列。

1. **订阅不能复制成本地配置，也不能上传成云端配置**。原因：复制出来的副本会带着节点 token，分享者撤销后也收不回来。新增错误码 `subscription_read_only`。
2. **创建分享要求来源配置已经同步完成**。服务端是按云端那一份配置做快照的。如果本机还有没推送的修改，客户端会先触发一次同步，并提示"等同步完成后再试"（`share_not_synced`），避免分享出去的内容和界面上看到的不一样。本地配置不能分享（`share_needs_cloud`）。
3. **full 分享"选全部代理"时，快照里记录的是当时那几个代理**。之后在来源配置里新增的代理，重新发布时不会自动加进去，需要新建一个分享。重新发布只按快照里已有的 ID 更新内容，被删掉的代理会被去掉。
4. **订阅参数只能在线修改**（template 的代理、p2p 的端口），因为它们保存在云端。启动不受影响，离线也可以启动。
5. **撤销要等订阅方的下一次同步才生效**，实测约 50 秒（60 秒轮询）。想更快可以以后加服务端推送，这不在 v1 范围内。
6. **分享数量上限只统计没撤销的分享**。撤销后的分享仍然显示在列表里，但不占名额。
7. **可以订阅自己的分享**。服务端没有禁止，方便自己在另一台机器上用。
8. **p2p 目标的 `serverUser` 取分享时所选节点的 frp `user`**。分享者在节点上设置了 user 时，访问方会自动带上，不需要额外配置。
9. **分享者只能看到订阅人数，看不到是谁订阅的**。PLAN 没有要求，如果需要，可以以后加一个订阅者列表（只显示昵称）。

## 怎么运行

```powershell
cd E:\frp_end\gogogo\client
wails3 build PACKAGE_MANAGER=pnpm                                     # 正式版 bin\MoeFrp.exe
wails3 build PACKAGE_MANAGER=pnpm EXTRA_TAGS=e2e APP_NAME=MoeFrp-e2e  # 端到端测试版
node .\scripts\e2e\run-phase4.mjs                                     # Phase 4 验收（约 3 分钟）
```

正式版 `bin\MoeFrp.exe` 体积 19.8MB，比 Phase 3 多约 0.6MB，主要是"分享"页的界面代码。
