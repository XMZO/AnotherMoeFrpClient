# 联机房间（虚拟局域网）

和朋友组成一个虚拟局域网：游戏里找"局域网"房间，或者直接连对方的虚拟 IP。客户端"联机"页。

## 怎么工作

- **房间**：面板上建房（房主）、发 8 位邀请码、别人输入加入；房主可以踢人，房主离开等于解散。成员有座位号 1–250，虚拟 IP 是 `10.241.0.<座位号>/24`。每人最多 10 个房间，每房最多 32 人。接口见 `shared/api/vnet.go`（`/api/v1/rooms*`）。
- **虚拟网卡**：Wintun（`client/third_party/wintun`：官方 0.14.1 的 amd64 `wintun.dll` 编在程序里，用 WireGuard 官方 Windows 客户端的 memmod 从内存加载，不在磁盘上释放文件）。建网卡要管理员权限：没有时"联机"页提示"以管理员身份重启"（带 `--elevated-from=<pid>` 重新启动，等原进程退出后再走单实例）。网卡叫 `MoeFrp`，跃点数 1（游戏的局域网广播从它发出），网络类别设为专用。
- **加密和转发**：每次进房间生成新的 WireGuard 密钥，公钥经实时通道告诉面板，面板推给房间里的其他人。WireGuard 的 peer 地址是座位号（`client/internal/vnet` 的 bind），由它决定怎么送：
  - **直连**：ICE 打洞（pion/ice，UDP，IPv4 / IPv6，本机地址 + STUN 反射地址）。座位号小的一方发起，打洞信息经实时通道转发；失败 45 秒后重试。
  - **中继**：打不通、还在打或者断了，经面板的实时通道转发（WebSocket 二进制帧：第一个字节是座位号）。
- **不受 VPN 的 TUN 模式影响**：打洞只用物理网卡（按名字排除 MoeFrp、Wintun、WireGuard、Tailscale、ZeroTier、Clash/mihomo、sing-box、TUN/TAP、VPN、Hyper-V、VMware、VirtualBox、Docker、WSL 等），socket 绑在物理网卡的地址上，Windows 按源地址选出口，不会被 TUN 接管；也不用 198.18.0.0/15（fake-ip）等地址。虚拟网段 `10.241.0.0/24` 避开了常见网段；VPN 开了 strict-route 拦本机虚拟网卡时，要在 VPN 里把这个网段设为直连。
- **局域网广播**：发往 255.255.255.255、10.241.0.255 和组播地址的包，复制成发给每个在线成员的单播（改目的地址、重算校验和）。

## 进联机页的把关

- 没登录：登录 / 游客加入 / 返回。
- 没有管理员权限：提示"安装"（以管理员身份重启，带 `--open=rooms` 回到联机页）/ 返回。
- 有权限但驱动没装：自动装（建一块网卡再关掉）。

## 游客

房主在"房间设置"里打开"允许游客"后，没登录的人用邀请码 + 昵称进来（`POST /api/v1/rooms/guest`），拿到只能用于这个房间的游客令牌，
用它连游客的实时通道（`/api/v1/rooms/guest/live`）。游客和成员共用座位号；房主能踢游客，离开或被踢后令牌作废。

## 中继节点（参考 Tailscale 的 DERP）

- 节点 agent 1.4.6 起内置中继：节点设置"开放与访问"里的"联机中继端口"（`vnetRelayPort`，TCP，新节点默认 7072，0 关闭；要在防火墙放行）。
  连接 `ws://节点地址:端口/vnet`，带面板签的票据（`nodeticket.SignVnet`：只能用于这个节点、这个房间的这个座位，24 小时，
  拿它登录不了 frps）。面板在成员列表里下发能用的中继和每个人的票据。
- 每个成员连着**两个收件中继**（主 + 备用，`api.VnetMaxHomes`）：主的按下面的规则选，备用是除主的以外延迟最低的
  （房主锁定了某个节点、或者选了面板时没有备用）。两条连接都一直保持，断了 1 秒后重连、每 5 秒检查一次。
  只把**真正连着的**报给面板（`relay` op 的 `homes`；`relay` 字段是主的，给旧版本客户端），面板在 peers 里转发给别人。
- 发中继包时，从对方连着的节点里挑一个自己也连着、自己这边延迟最低的；一个节点出问题马上换另一个，都不行才走面板。
  两人用不同的中继也通，不需要中继之间转发。收件人没连着的节点会把包丢掉（黑洞），所以收件中继必须一直连着、只报连着的。
- 选择：房主设默认中继、可以锁定（锁定后所有人只能用它）；不锁定时成员可以在联机页自己换：自动（房主的默认，没设就测延迟选最近的）、
  面板、某个节点。节点都不行时用面板中继。

## 禁止直连

房主可以在房间设置里打开"禁止直连"（`noDirect`）：成员之间不打洞，全部经中继（节点或面板）转发，
也就不会互相看到公网 IP（打洞要交换公网地址）。切换马上生效：打开时断掉已有的直连，关掉时重新打洞。
旧版本客户端不认识这个设置，照样打洞。

## 冗余发送（降低丢包）

MC 这类用 TCP 的游戏，丢一个包整条连接都要等重传，丢包率一高就回弹、卡区块。直连走 UDP，晚上运营商限速时丢包可能到 10% 以上。
所以：延迟探测（每 2 秒一次，探测和回复都只走直连）顺便统计直连丢包，最近 30 次里有丢的，就把发给这个人的每个包
同时经中继（他连着的、我也连着的节点）再发一份；连续 30 次都没丢才关。WireGuard 自带防重放，后到的那份对方直接丢掉。
中继那份经每条中继连接的发送队列异步发，中继堵了不拖慢直连。成员列表里显示丢包率和"直连+冗余"。
打洞用的 UDP socket 收发缓冲区调到 4MB（`bufnet.go`）：Windows 默认只有几十 KB，MC 走动加载区块这种突发会把它塞满，
包在本机就被丢了。

## 成员延迟

每 2 秒给每个在线成员发一个探测包（第一个字节 0xFE，后面 8 字节发送时间），对方原样回 0xFF。探测包和 WireGuard 的包走同一条路
（直连 / 节点中继 / 面板），量出来的就是游戏数据实际的往返延迟，显示在联机页的成员列表里。WireGuard 的包第一个字节是 1–4，不会混；
旧版本客户端收到探测包会当无效包丢掉（只是量不出延迟）。

## 房间名

房主在房间设置里改名（PATCH 带 `name`，不带就不改）。面板在成员列表（peers）里带上 `roomName`，在房间里的成员马上看到新名字。

房主可以换邀请码（`POST /api/v1/rooms/{id}/code`，联机页邀请码旁边的"换码"）：旧码马上作废，防止泄露后被滥用；
已经在房间里的成员和游客不受影响。peers 里带 `roomCode`，在线成员马上看到新码。

## 语音

联机页的"加入语音"（前端 `client/frontend/src/voice.ts`）：像 Discord 的语音频道，轻量版。
- 每两个人之间一条 WebRTC 连接（网状）。只交换虚拟网（10.241.0.x）和 mDNS 的候选地址，语音包走虚拟网：直连、节点中继、
  面板中继都能通，不暴露真实 IP，不需要 STUN/TURN。降噪、回声消除、自动增益用 WebView2（Chromium）自带的，编码 Opus。
- 协商借用 vnet 的 signal：Data 是 `{"t":"voice",...}`，面板原样转发；客户端识别 t=voice 转给前端（事件 `vnet:voice`），
  打洞引擎不认识，旧版本会忽略。进语音时向在线成员发 hello，对方回 here，座位号小的一方发 offer（不 trickle，一条消息带全部候选）。
- 麦克风权限在 WebView2 里直接允许（main.go 的 Permissions）。没有麦克风时只能听。
- 设备：语音条的"设备"里选麦克风 / 扬声器（默认跟随系统，选择存在本机）。插拔设备时列表自动刷新；选中的设备拔掉了回到默认；
  换麦克风用 replaceTrack，不用重新协商。
- 房主：房间设置里"允许语音"（`noVoice`），成员列表里给单个人禁言（`muted`，座位号）。被禁言的人发不出声，别人也不播他的声音。
  PATCH 不带 `noVoice` / `muted` 时保持原样（旧版本客户端改设置不会把它们清掉）。

## 局域网发现（广播 / 组播）

游戏发现局域网房间用广播或组播（MC Java：IPv4 224.0.2.60:4445；开了 IPv6 优先时用 IPv6 ff75:230::60:4445）。

- 出口：程序没指定网卡时，Windows 按"路由跃点 + 网卡跃点"选出口，别的虚拟网卡（Radmin VPN、ZeroTier 等）跃点也很低时会打平，
  包从别的网卡发出去。所以进房间时把虚拟网卡的跃点和 224.0.0.0/4、255.255.255.255/32、ff00::/8 路由的跃点都设成 0
  （`store=active`，网卡删掉就没了）；在房间里每 5 秒用 GetBestInterfaceEx 检查一次，被抢了就重新设置（被反复抢就停 5 分钟）。
- 转发（bcastTun）：广播 / 组播包整个封装进发给每个在线成员的 IPv4 包（协议号 253），对方拆开后原样交给系统。
  只改成单播不行：加入组播组监听的程序（MC）收不到发给本机 IP 的单播。
- IPv6：每个成员另有 IPv6 地址 `fd4d:6f65:4672::<座位号十六进制>`（客户端按座位号自己算，WireGuard 也放行），
  MC 的发现包在 IPv4 和 IPv6 之间互相翻译一份，一边只发 IPv4、另一边只听 IPv6 时也能发现、能连上。

## 已知限制

- 只支持 Windows x64；需要管理员权限。
- 打不通时走中继，延迟取决于到中继节点（或面板）的线路；打洞成功后直连。
- 一次只能进一个房间。
